# Automated Validation

This section describes the planned technical implementation, developed in T3.4 & T4.4 under KR06, for checking FMs automatically. The approach combines several methods instead of relying on one: adversarial robustness testing, uncertainty calibration, explainability, fairness (for example per-region accuracy gaps) and privacy checks such as membership inference. The results go to an aggregator that produces a machine-readable score card, which can act as an entry gate for models in the FM registry. The validation is designed to be model-agnostic and to work with input and output access only, with extended modes when a partner chooses to expose model internals. It is first built against an open FM and then applied to the consortium FMs once they are released (D3.2, D4.1), and its methods and implementations are documented in D4.2. The section includes a table that separates what is mandatory in this version (documentation, data-level checks and minimum reporting) from what is planned to become mandatory in version 2 (D2.2) once the validation tools have been tested on the first consortium foundation models.
